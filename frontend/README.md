# ZERO TABLE 프론트엔드

React 19 · Vite · react-router. 백엔드 API는 `https://webframework.monithub.org`를 사용합니다.
API 명세는 [backend/docs/SCORING.md](../backend/docs/SCORING.md), [FRONTEND.md](../backend/docs/FRONTEND.md)를 기준으로 합니다.

## 1. 처음 준비

| 프로그램 | 확인 |
|---|---|
| Git | `git --version` |
| Node 20 이상 | `node --version` |

```bash
cd frontend
npm ci          # 라이브러리 설치. 처음 한 번, 또는 package-lock.json이 바뀌었을 때
npm run dev     # 개발 서버 http://localhost:5173 (저장하면 바로 반영)
```

로컬 백엔드로 시험할 때만 `frontend/.env`에 `VITE_API_BASE_URL=http://localhost:8080/api/v1`을 적고 개발 서버를 다시 켭니다. 없으면 운영 서버를 씁니다. `.env`는 커밋하지 않습니다.

## 2. 이슈 진행 순서

1. **이슈 확인**: 내 담당인지, "기다리는 것"이 끝났는지 본다.
2. **최신 main에서 브랜치 만들기**
   ```bash
   git switch main
   git pull
   git switch -c feat/report-price-notice
   ```
   이름은 `종류/영어-설명`.
3. **수정**: 이슈 "할 일"의 파일만. "고치지 않는 곳"과 `backend/`는 건드리지 않는다.
4. **확인**: `npm run lint`, `npm run build` 통과 + 이슈 "확인 방법"대로 브라우저 확인.
5. **커밋**
   ```bash
   git add 고친-파일-경로          # git add . 은 쓰지 않는다
   git diff --cached               # 올라갈 내용 확인
   git commit -m "feat: 보고서 가격 비교를 안내 문구로 교체"
   git push -u origin feat/report-price-notice
   ```
6. **PR**: main으로. 아래 PR 양식대로.
7. **머지** (팀 확인 필요): frontend/만 바꾼 PR은 올린 사람이 "Create a merge commit"으로 머지.
8. **다음 이슈**: 같은 파일을 고치는 이슈는 앞 PR이 머지된 뒤 2번부터.

### 혼자 정해도 되는 것 / 단톡에 올릴 것

- **혼자 정함**: 컴포넌트 나누기, 변수·함수 이름, 내부 구현 → PR "작업자가 정한 것"에 적기
- **단톡에 올림**: API 요청·응답 형식, 점수 계산 규칙, 화면에 보이는 안내 문장, 다른 사람 담당 파일 수정

## 3. 규칙

| 종류 | 언제 |
|---|---|
| `feat` | 기능 추가·변경 |
| `fix` | 버그 수정 |
| `refactor` | 동작은 그대로, 구조만 변경 |
| `chore` | 정리·설정 |
| `docs` | 문서 |

- 커밋 메시지: `종류: 한국어 내용`. 커밋 하나에 변경 하나.
- `.env`, 데이터 파일(csv, xlsx), API 키는 커밋하지 않는다. 실수로 올렸으면 바로 단톡에.

### 같이 쓰는 파일

| 파일 | 규칙 |
|---|---|
| 다른 사람 담당 파일 | 고치기 전에 단톡에 알린다 |
| `index.css` | 새 스타일은 `/* ---------- 구역 이름 ---------- */` 아래에 모아 추가. 다른 구역은 고치지 않는다 |
| `package.json` | 패키지 추가는 단톡에 알린다 (팀원도 `npm ci` 필요) |
| `api.js`, `format.js` | 함수 추가는 괜찮음. 기존 함수의 동작을 바꾸면 단톡에 알린다 |

## 6. 코드 작성 규칙

### 주석

- 파일 맨 위에 이 파일이 맡은 일을 한 줄로 쓴다.
- 코드만 봐서는 알 수 없는 "왜"만 쓴다. 코드를 그대로 다시 말하는 주석은 쓰지 않는다.
- 만들 때 메모(시안, 프로토타입, 이슈 지시문)는 쓰지 않는다.
- 문체는 "~한다", 짧은 한 문장.

좋은 예 (`api.js`): 코드만 봐서는 모르는 이유를 알려 준다.

```js
// 시간대마다 길이가 달라(오전 5시간, 점심 3시간 …) 시간당 매출로 바꾼 뒤
// 가장 높은 시간대를 100으로 맞춘다.
```

나쁜 예 (`DemandSection.jsx`): CSS가 하는 일을 말로 다시 설명한다.

```jsx
{/* 3대 차트 대시보드: 화면이 줄어들면 깨지지 않고 자연스럽게 1~2열로 감싸지도록 minmax 설정 */}
```

### 이름

- 값이 여러 개면 복수형(`salesModes`), 참·거짓은 `is`·`has`로 시작한다.

### 값과 스타일

- 고정 값은 이름 있는 상수로 둔다. 한 파일에서만 쓰면 그 파일 위에, 여러 파일이 쓰면 `constants/`에.
- 스타일은 `index.css`에 둔다. 데이터에 따라 바뀌는 폭·높이만 `style={{}}`로 쓴다.
- 화면 전용 클래스 이름은 화면·구역 이름으로 시작한다(`compare-table`, `demand-fact-card`).

### 코드

- 같은 계산이 두 곳에 생기면 함수 하나로 모은다.
- 서버 응답 값은 실제 응답을 확인하고 쓴다. 오지 않는 값을 대비한 코드를 미리 만들지 않는다.

## 7. 코드 구조

### 폴더 구성

```
src/
├─ pages/          화면 (화면 하나 = 파일 하나)
│  └─ report/      상세 보고서 (구역 01~05가 파일 하나씩)
├─ components/     여러 화면이 같이 쓰는 조각 (선택 버튼, 요약 줄, 안내 상자)
├─ state/          입력값과 분석 결과를 모든 화면이 같이 보는 보관함
├─ constants/      고정 값 (화면 주소, 질문 목록, 업종 코드)
├─ api.js          서버와 주고받는 함수
├─ format.js       숫자를 화면 글자로 바꾸는 함수 (원, 명, %)
└─ index.css       스타일
```

### 화면 흐름

```
시작 ─┬─ 간단 분석 → 기본 입력 → 분석 중 → 간단 결과
      │                                       │ 상세 분석하기
      │                                       ↓
      └─ 상세 분석 → 기본 입력 ─────────→ 질문 1 → 2 → 3 → 결과 열기 → 분석 중 → 보고서
```

| 화면 | 파일 |
|---|---|
| 시작 | `pages/StartPage.jsx` |
| 기본 입력 | `pages/BasicInputPage.jsx` |
| 분석 중 | `pages/AnalyzingPage.jsx` |
| 간단 결과 | `pages/SimpleResultPage.jsx` |
| 추가 질문 1~3 | `pages/QuestionsPage.jsx` |
| 결과 열기 | `pages/ResultOpenPage.jsx` |
| 상세 보고서 | `pages/report/ReportPage.jsx` |

### 입력한 값이 보고서가 되기까지

1. **입력**: 기본 입력과 추가 질문에서 고른 답은 공용 보관함(`state/AnswersProvider.jsx`)에 모인다.
2. **분석**: 분석 중 화면이 보관함의 답을 서버에 보내고, 점수와 상권 자료를 받아 온다.
3. **저장**: 받은 결과는 분석할 때의 입력값과 함께 보관함에 저장된다. 새로고침해도 남고, 탭을 닫으면 지워진다.
4. **보고서**: 보고서는 저장된 결과를 구역(01~05)마다 나눠서 보여 준다.

분석한 뒤 답을 바꾸면 보고서 위에 "다시 분석해야 해요" 안내가 뜬다. 상권 자료 중 일부를 못 받았을 때는 받은 자료만 보여 주고, 못 받은 자료는 [다시 불러오기]로 따로 받는다.

### 사용 기술

| 기술 | 쓰는 곳 |
|---|---|
| React | 화면을 조각으로 나눠 만들고, 같은 조각을 여러 화면에서 다시 쓴다 |
| react-router | 화면마다 주소를 붙여 뒤로가기와 새로고침이 되게 한다 |
| Context | 1단계에서 고른 답을 보고서까지 들고 가는 공용 보관함 |
| Vite | 개발 서버와 빌드 |

보고서의 막대 그래프는 막대 높이만 바뀌는 단순한 모양이라 그래프 라이브러리 없이 직접 그렸다.
